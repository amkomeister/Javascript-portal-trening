# Lærarinnføring og ny kvalitetskontroll

Utgangspunkt: `23966f9413bcb4b699a489ff1b6f074905dc4841`. Eigaren bad om grundig kontroll, lærarguide og klargjering for kommunal drift. Ingen publisering er utført.

## Arbeidsplan og vurderingar

1. Lærarguide ved første innlogging, seks korte steg, alltid tilgjengeleg att. Fullføring blir lagra på lærarkontoen etter svar frå serveren.
2. Prøv gruppemedlemskap, tilgang mellom lærarar, tilbakemeldingar og vern mot tap av arbeid; rett observerte feil.
3. Køyr heile lokalpakken, produksjonsbygg og isolerte emulatorprøver. Dokumenter kva som framleis krev kommunen sitt miljø.
4. Éin ny uavhengig gjennomgang av endringane, deretter nødvendige rettingar og ny validering.

Pre-flight: Guiden bruker eksisterande brukarprofil og lærarrolle. Innlogging må bevare guideversjon. Lærarrommet må returnere same livssyklusgrensesnitt som arbeidsflata dersom tilbakemeldingar skal vernast ved navigering og kontobyte.

Ruling: Bruk eksisterande lyse verkstaddesign og eit avgrensa dialogvindauge utan nye avhengigheiter — bestillinga gir allereie retning og gjennomføringsløyve — kostnad om feil: retting av guideinnhald og navigering.

Ruling: Lokal gjennomføring kan ikkje stadfeste ekte Google-kontoar eller kommunal produksjonsdrift — desse blir eigne opne kontrollar, ikkje automatisk godkjende — kostnad: kommunen må fullføre akseptansen før elevbruk.

## Evidens

- Før endringar: `pnpm test` 80/80 PASS. `pnpm audit --json`: 0 kjende sårbarheiter. Dette er avgrensa automatiske kontrollar.
- Chrome på port 5175 er open for eigaren. Testar bruker port 5176/8086 og syntetiske kontoar; personleg Kodeverkstad på 5173 blir ikkje endra.
- Kjeldeobservasjon: ingen lærarguide, inga oppdateringshandling for medlemslista og ingen vern for ulagrede lærartilbakemeldingar.
- Ny guide: manglande endepunkt og dialog reproduserte før implementering; API- og nettlesarprøva består etterpå. Guidefullføring blir lagra per konto og kan utsetjast eller prøvast på nytt etter nettfeil.
- Tilgangsmatrisa prøver eigar, annan lærar, elev, annan elev, ventande medlemskap og fjerna medlemskap. Ingen tilgang utanfor godkjend gruppe i desse testane.
- Reprodusert feil: ei ny innmelding under samtidig fjerning av tilgang kunne gjenopprette godkjenninga. Innmelding bruker no ein transaksjon som aldri skriv over eit eksisterande medlemskap (RED → GREEN).
- Reprodusert feil: lærartilbakemeldingar mangla revisjonskontroll. Serveren bevarer no begge utgåver i eksisterande konfliktsamling og svarar 409; læraren vel utgåve (API RED → GREEN, nettlesarval under validering).
- Første samla nettlesarkøyring: 18/19 PASS; éin eldre test valde «Sjå arbeid» utan å avgrense til si gruppe. Testen er avgrensa til rett gruppe; ingen produktfeil på denne observasjonen.
- Backup/gjenoppretting på eigen emulatorport 8087: PASS medan eigaren sin lokale app var open.
- Eigaren stadfesta «ikkje enno» for kommunale skyopplysningar. Desse står framleis opne.
- Etter retting av gruppa i den eldre testprøva: full `pnpm test:e2e` 19/19 PASS, inkludert dei nye lærarprøvene, ti samtidige elevar og alle Snake-stega.
- Produksjonskode køyrd lokalt med syntetisk konfigurasjon: HTTP-smoke PASS for bygde ressursar, Secure/HttpOnly-cookie, verna API og stengd lokal innlogging. Ingen ekte Google- eller Firestore-tilgang i denne prøva.
- Tre ekstra UI-prøver består: feil rekkjefølgje på elevsvar, skriving medan ein annan elev blir henta, og skriving medan tilbakemeldinga blir lagra.
- Samla før uavhengig kontroll: `pnpm test` 89/89 PASS; `pnpm test:e2e` 19/19 PASS; `pnpm test:preview` 5/5 PASS; `pnpm build` PASS; `pnpm test:emulator` PASS. Vite varslar om store kodepakkar (CodeMirror/QuickJS); byggjetesten feilar ikkje.

Ruling: Bruk eit utkast til pull request for Linux-/containerkontrollen på GitHub — Docker og WSL er ikkje installerte lokalt, og eksisterande løyve omfattar oppdatering av prosjektet på GitHub — kostnad: ein avgrensa CI-køyring; inga samanslåing eller publisering.

Ruling: Gi lærartilbakemeldingar same vern mot samtidig overskriving som elevkode — avdekt datatap og den godkjende planen krev revisjonskontroll — kostnad om feil: eit ekstra val ved samtidige lærarendringar. Eksisterande vurderingar utan revisjon blir lesne som versjon 0.

## Opne kontrollar

- Kommunen: prosjekt-ID, billing, skuledomene, region, læraridentitetar, lagringstid/sletting og driftsansvar.
- Ekte Google-innlogging, Cloud Run, feil-/kostnadsvarsling og gjenoppretting i kommunen sitt miljø.
- Lærar/elevprøve og reelle skulemaskiner. Automatiske testar kan ikkje stadfeste læringsutbytte.
